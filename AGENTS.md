## Documentation structure

This is a documentation-as-contract repository: interfaces/types are
specified in Markdown before (or alongside) implementation. Docs are
partitioned so no two locations are both plausibly authoritative for the
same concept:

- `docs/contracts/` — normative type/interface definitions. If code and a
  contract file disagree on a field, the contract is not automatically
  right — check the contract's own `Status` line (`DESIGNED` /
  `IMPLEMENTED` / `VERIFIED`) and, if needed, run
  `.claude/skills/contract-implementation-sync` before assuming either
  side is stale.
- `docs/architecture.md` and `docs/architecture/` — explanatory design
  rationale, not normative type shapes.
- `docs/decisions/` — ADRs and the decision ledger recording why a
  contradiction was resolved a particular way.
- `README.md` — states the project's explicit legal/authorization
  boundary (see below) and product framing.

## Legal / authorization boundary

This project is explicitly scoped to authorized/licensed/public-domain/
user-owned content only (see `README.md`'s "StreamForge is not designed
to..." section and `docs/architecture.md` §1). Before adding or changing
any source-adapter or provider integration, run:

```bash
python3 .claude/skills/authorization-boundary-scan/scripts/scan_authorization_boundary.py src package.json
```
